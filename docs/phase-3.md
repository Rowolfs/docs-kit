# Фаза 3 — модель и установка

<div class="lvl lvl-1" markdown>

## Кратко

Реализованы реестр компонентов, модель файлов и папок, команды `show`, `find`,
`deps`, `changed`, генерируемая карта и GitHub-ссылки с commit SHA.
Базовая установка перенесена сюда из фазы 7 по уточнению пользователя.

Установщик создаёт структуру и заготовки со статусом `planned`, добавляет
правила в `AGENTS.md`. Объяснения пишет агент по прочитанному коду. После
проверок агент отправляет изменения; GitHub Actions собирает сайт.
`docs-check` ещё не существует: выбор реализации относится к фазе 4.

</div>

<div class="lvl lvl-2" markdown>

## Подробно

[Модель](components/model.md) не читает содержимое исходников. Список файлов
даёт Git, принадлежность и зависимости — `components.yaml`. JSON делится на
страницы до 30 КиБ и не коммитится. Неописанные реестром файлы видны в общей
структуре. Нет анализа символов, импортов и автоматического написания прозы.

[Установщик](components/installer.md) загружает точную версию во временный
checkout и запускает Python. Повторный вызов сохраняет написанные страницы,
конфликты проверяются до изменений. Существующий текст `AGENTS.md` сохраняется.
Работает и репозиторий без первого коммита: у модели тогда нет SHA-ссылок.

Сайт получает сгенерированную карту и только перечисленные генератором JSON.
Посторонние файлы из каталога модели не публикуются. `file:`-ссылки разрешаются
в готовом HTML, текст исходного Markdown остаётся прежним.

## Полностью

Проверены 55 тестов. Проверки включают unit-тесты временных Git-репозиториев, CLI, граничные размеры JSON,
безопасность выходных каталогов, повторная установка и откат при ошибке.
Интеграционный тест выполняет настоящую строгую сборку установленного проекта
с локальной заглушкой Mermaid, без сети. Отдельный браузерный demo использует
настоящий Mermaid и проверяет страницу карты, JSON и SHA-ссылки.

Первый браузерный CI остановился до тестов: `ubuntu-latest` перешёл на
Ubuntu 26, которую закреплённый Playwright не поддерживает. Для браузерного
job закреплён Ubuntu 24.04; версию Playwright не меняли.


Публичный Bash/wget-загрузчик релиза проверен в отдельном Git-репозитории:
создал заготовки, сохранил существующие правила AGENTS.md, при повторном запуске
сохранил написанный текст и не изменил HEAD. Команда `--model changed` через
тот же загрузчик определила новый файл и затронутый компонент.

Подтверждения: [PR #5](https://github.com/Rowolfs/docs-kit/pull/5),
[успешный PR CI](https://github.com/Rowolfs/docs-kit/actions/runs/44501089364),
[CI на main](https://github.com/Rowolfs/docs-kit/actions/runs/44501529261),
[Pages workflow](https://github.com/Rowolfs/docs-kit/actions/runs/44501840093),
[релиз v0.3.0-alpha.1](https://github.com/Rowolfs/docs-kit/releases/tag/v0.3.0-alpha.1).

Ограничения: секреты исключаются по типовым именам, это не сканирование
содержимого. Нельзя относить файл сразу к двум компонентам. Поддержаны
GitHub HTTPS/SSH origin и ветка публикации `main`; Pages нужно включить отдельно.
Установщик требует сети, Bash, Git и Python 3.11+ с venv. Документация существующей
структуры с конфликтующими именами объединяется явно. Автоматический вызов
агента и автоматический push самим установщиком отсутствуют.

До фазы 4 агент проверяет достоверность, ссылки и секреты вручную и использует
существующие проверки кода проекта. Не выдаёт отсутствие docs-check за успешный
запуск. Перед фазой 4 требуется сравнение собственных проверок с LiveDoc и
решение пользователя. Финальная упаковка template repo остаётся в фазе 7.
