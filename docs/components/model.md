# Модель проекта

<div class="lvl lvl-1" markdown>

## Кратко

Модель связывает компоненты из `components.yaml` с файлами и папками Git-проекта.
Она генерируется при сборке, не хранит содержимое кода и не коммитится.
[Карта кода](../_generated/code-map.md) показывает фактические пути и зависимости,
объявленные в реестре. Объяснения назначения кода пишет агент после чтения кода.

</div>

<div class="lvl lvl-2" markdown>

## Подробно

Скрипт [docs_model.py](file:scripts/docs_model.py) получает отслеживаемые и новые неигнорируемые
файлы через Git, исключает служебные каталоги, документацию и типовые секретные
файлы. Шаблоны `paths` определяют принадлежность файлов компонентам. Пересечение
компонентов, неизвестная зависимость и отсутствующая страница приводят к ошибке.
Неописанные реестром файлы остаются в общей структуре модели.

Сборщик добавляет карту во временную документацию и публикует JSON рядом
с ассетами. Авторские Markdown-файлы не переписываются. Ссылки `file:` в готовом
HTML превращаются в GitHub URL с SHA коммита; для отсутствующего в коммите
файла или неизвестного пути сборка завершается ошибкой.

<div class="lvl lvl-3" markdown>

## Полностью

Локальный вызов из checkout движка:

```bash
.venv/bin/python scripts/docs_model.py --project-dir . build
.venv/bin/python scripts/docs_model.py --project-dir . show model
.venv/bin/python scripts/docs_model.py --project-dir . find scripts
.venv/bin/python scripts/docs_model.py --project-dir . deps build
.venv/bin/python scripts/docs_model.py --project-dir . changed --base HEAD
```

Параметры проекта указываются перед подкомандой. `changed` сравнивает рабочее
дерево с базой, учитывает удаления и новые файлы. Перед сравнением с базовой
веткой PR нужно получить её через Git. Модель не выводит зависимости из импортов,
не анализирует символы и не даёт гарантий обнаружения всех секретов по имени.
Строгий сканер документации относится к фазе 4.

Выход: `build/model/index.json`, `components/<id>.json` и продолжения `next`.
Каждый JSON ограничен 30 КиБ; если нужно, записи делятся на страницы. Записи
содержат `id`, `kind`, `parent`, указатель `code`, иногда `doc` и данные реестра.
Поле строк пока пустое: первая версия работает на уровне файлов и папок.

SHA обозначает коммит, а список файлов может включать незакоммиченные изменения.
На карте новый файл без объекта в этом коммите показывается без GitHub-ссылки.
Модель служит навигацией, а не анализом смысла кода.
