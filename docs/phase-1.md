## Как устроено

Сборщик читает тонкий конфиг и Markdown, создаёт временный проект и вызывает
Zensical. Reusable workflow использует собственный SHA для движка и отдельно
получает исходники вызывающего проекта. Публикация получает готовый артефакт.

### Что входит в каркас

| Часть | Назначение |
| --- | --- |
| `scripts/build_site.py` | Валидация входов, временный проект, вызов Zensical, выходная статика |
| `theme/` | Минимальные проверенные элементы интерфейса и точный локальный Mermaid |
| `demo/` | Отдельный тонкий проект: только собственные страницы и конфиг |
| `tests/` | Контракты изоляции, целостности ассетов и сохранения контента |
| `.github/workflows/build.yml` | Reusable сборка и отдельный необязательный deploy-job |
| `.github/workflows/ci.yml` | YAML, unittest, браузерный demo и вызов reusable workflow текущей ревизии |
| `.github/workflows/docs.yml` | Вызов опубликованной версии движка после успешного CI на `main` |

Сам docs-kit и независимый demo используют один сборщик. Эксперимент фазы 0
сохранён отдельно. Типовой контракт описан в [подключении](connect.md);
полноценный template repo остаётся задачей фазы 7.

### Версии и публикация

Reusable job извлекает собственные `workflow_repository` и `workflow_sha`
из контекста `job`, проверяет значения и получает соответствующий checkout.
Второй checkout содержит проект. Пустой SHA завершает job ошибкой, а не
подменяется веткой по умолчанию.

Публикация идёт после успешного CI на push в `main`; используется именно
проверенный SHA контента. Перед `deploy-pages` он сверяется с текущим `main`:
поздно закончившийся старый CI не должен заменить свежий сайт. Deploy-job
сериализован. PR собирает Pages-артефакт, но не публикует его.

GitHub проверяет максимальные права вложенных jobs даже при пропущенном
deploy-job. Поэтому caller объявляет `pages: write` и `id-token: write`;
исполняемый build-job явно ограничен чтением. PAT в workflows не используется.

## Детали

### Результаты проверок

- `make build` и `make demo`: Zensical собрал оба проекта в strict-режиме
  без предупреждений.
- `make test`: 17 контрактных unittest прошли. Проверены конфиг, границы
  каталогов, сохранение авторских байтов, отказ сборщика и SHA-256 Mermaid.
- `make lint-yaml`: без замечаний; actionlint 1.7.12 также прошёл.
- Chromium 142: загрузка страниц, накопительные уровни, сохранение выбора,
  instant navigation, настоящий клик мышью по Mermaid, две темы, ширина 390 px.
- Отдельно локально открыты архитектура, подключение и отчёты обеих фаз;
  архитектурная диаграмма отрисовалась в SVG.
- На публичном Pages повторён браузерный smoke: нет ошибок страницы,
  консоли, HTTP, сетевых запросов и внешних ассетов.

### Воспроизведение

Команды сборки и браузерной проверки приведены в README репозитория.
Для публичного сайта:

```bash
/tmp/docs-kit-browser/bin/python demo/check_browser.py \
  --url https://rowolfs.github.io/docs-kit/ \
  --browser /usr/bin/chromium-browser \
  --output build/phase1/published
```

Путь к Chromium можно заменить; без `--browser` используется браузер,
установленный Playwright. Подготовка сборки требует сеть для зависимостей
и первого скачивания Mermaid. Чтение готовой статики не требует CDN.

### Что не проверено и ограничения

- GitHub Enterprise Server не поддерживается: нужны новые поля контекста
  GitHub.com. Приватный проект, другая организация и custom domain пока не
  проверены. Отдельный потребитель в другом репозитории не создавался;
  внешний вызов по тегу проверен на репозитории самого docs-kit.
- Firefox, Safari, настоящий телефон и полная доступность не проверены.
- Запоздавший старый deployment специально не воспроизводился; защита
  реализована сверкой SHA, путь публикации текущего SHA проверен в Actions.
- Права защиты ветки `main` пока не настроены; обязательные проверки будут
  обсуждаться в фазе 4. Успешный CI сейчас не является запретом обхода.
- Неподвижность релизного тега — правило выпуска; отдельная GitHub ruleset
  защиты тегов пока не настроена. Исправления движка требуют новой версии.
- Lock Python фиксирует версии без хэшей; размер полного Mermaid около
  5.3 MiB. Оптимизация и дополнительные гарантии поставки пока отложены.

Ограничения последующих фаз: нет модели кода, docs-check, журнала, статистики,
полного шаблона, финальной темы и счётчика слов. Скрытые уровни пока не
синхронизированы с оглавлением и поиском. Перед фазой 4 нужно предложить
сравнение собственных проверок с LiveDoc и дождаться решения пользователя.
